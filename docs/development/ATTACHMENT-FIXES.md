# 附件与截图修复记录

日期：2026-09-08。生产镜像 `haudi-openwebui:0.11.3-research-v4`，实际镜像 ID 见 `sources.lock.json`。

## 问题与修复

1. 文本上传能提取内容，却报嵌入模型未加载，聊天提示找不到引用。原因是原镜像关闭自动模型下载且本地没有模型；提取文本成功不代表建立向量索引成功。现安装固定版本的 `intfloat/multilingual-e5-small` 并启用索引，使用 `query: ` / `passage: ` 前缀、单条批处理和 2 个 CPU 计算线程。
2. 引用网页报查询知识库错误，来自网页保存向量时调用了同一个缺失的模型。启用模型后，实际网页建立索引和查询通过。
3. 截图直接调用 `getDisplayMedia`，失败只写控制台，生产压缩还移除了日志。新共享处理函数在 HTTP / 不支持的浏览器下显示说明并打开截图文件选择入口；安全连接下正常截屏，取消或失败给出反馈，所有已申请的屏幕流都在 finally 释放。聊天和频道两处截图入口均更新。

浏览器直接截屏仍受安全上下文约束。公网 HTTP 上不能绕过该限制；用户可以选择已有截图，或使用系统截图后粘贴。要直接弹出浏览器屏幕选择器，应使用 HTTPS 或本机 SSH 隧道的 localhost 地址。参见 [MDN getDisplayMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getDisplayMedia)。

模型支持多语言及所需前缀，依据 [模型发布说明](https://huggingface.co/intfloat/multilingual-e5-small)。服务器无法直连模型站点，下载使用配置记录的镜像域名，固定提交并依据该镜像返回的 LFS SHA-256 校验权重；模型运行时保持离线模式，不执行远程模型代码。模型文件不提交到 Git。

## 重现部署

在开发机执行 `python scripts/package_deploy.py`，将 `.build/deploy` 所需材料上传到服务器部署根目录。沿用维护文档中的已授权 SSH 配置；以下脚本通过 `remote.py` 在服务器执行：

1. `install-retrieval-model.sh`：下载到持久目录，校验权重。
2. `configure-retrieval.sh`：备份检索设置，通过管理 API 更新模型和分块参数，写入前缀及线程环境变量。
3. `build-workstation-branding.sh`：从固定镜像构建 v4，使用上传的 `screen-capture.js`。同一文件也由补丁生成脚本用于完整源码开发。
4. `deploy-research-copy.sh`：重建容器加载环境变量，健康检查失败回退旧容器。
5. `reindex-failed-files.sh`：重建此前失败的文件索引，保留文件和归属；没有清空向量库或业务数据。
6. `verify-retrieval.sh`：真实上传合成文本、中文查询、公开网页索引和带引用的模型回答；会调用聊天模型并删除测试上传文件。

部署脚本仍面向当前服务器，不能直接当通用新机安装器。需要回退配置时使用 `retrieval-backup-*`；仅回退 UI 容器不回退数据库中的检索设置。若更换成不同嵌入模型，必须重新规划已有索引重建，不能混用不同模型的向量。
